# ESI Mail Implementation Plan (twenty-third batch)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add full coverage for ESI's "Mail" tag (9 endpoints: list/get mail, get labels, get
mailing lists, send mail, create/delete label, update/delete mail) as 9 new MCP tools, folding
into the same shared PR #6 branch as every prior batch.

**Architecture:** Same two-layer split as every prior batch. `esi/mail.go` wraps the 9 generated
`MailAPIService` methods, all "my own character" style (`int64(c.characterID)`, never a
caller-supplied character ID — verified against every one of the 9 paths' OAuth2 security
requirements in `esi/api/openapi.yaml`). `mcp/mail.go` exposes 9 tools on top of that: 4 read
(reusing `characterExists`/`ErrCharacterNotFound`), 5 write (verb-first names, descriptions state
they change state on EVE's server, per this project's established write-tool convention).

**Tech Stack:** Go 1.26.1, `github.com/fnt-eve/goesi-openapi` v0.0.37, `github.com/modelcontextprotocol/go-sdk` v1.6.1.

## Global Constraints

- Baseline before this plan: 137 MCP tools, branch `worktree-esi-access-list-activities`,
  PR #6 (open). This plan brings the count to 146.
- All 9 endpoints require an `esi-mail.{read_mail,send_mail,organize_mail}.v1` character-scoped
  OAuth2 scope — verified directly against `esi/api/openapi.yaml`'s security blocks for every one
  of the 9 `/characters/{character_id}/mail...` paths. All private, no corp-scoped variants.
- **`GetCharactersCharacterIdMail`'s pagination is NOT this project's usual page/`X-Pages` style.**
  The generated request builder's only optional params are `.Labels([]int64)` and
  `.LastMailId(int64)` — there is no `.Page()` setter and no `X-Pages` response header semantics
  for this endpoint (ESI's mail listing returns "the 50 most recent" and pages backwards via a
  mail-ID cursor). Do not introduce `totalPagesFromHeader` (`esi/contracts.go`) here — it does not
  apply and would invent an ESI feature that doesn't exist for this endpoint.
- Every `esi/` method's `.Execute()` call MUST route through the existing `describeError(err, resp)`
  helper (`esi/error.go`) before wrapping with `fmt.Errorf` — reused, never redeclared.
- Reuse `characterExists(store *config.Store, characterID int32) (bool, error)` and
  `ErrCharacterNotFound` from `mcp/character.go` — do not redeclare.
- The recipient type (`PostCharactersCharacterIdMailRequestRecipientsInner{RecipientId int64, RecipientType string}`)
  is a **flat struct with a string discriminator**, reused identically across the send-mail request
  and both read-mail response shapes (list headers and single-mail detail) — confirmed identical
  generated type, not just structurally similar. `RecipientType` stays a plain Go `string` (not an
  invented enum type) since `goesi-openapi` itself only generates a string field despite
  `openapi.yaml` documenting valid values (`alliance`/`character`/`corporation`/`mailing_list`) —
  document those values via the `jsonschema` tag instead of enforcing them in Go.
- **Standing convention (added after the Killmails batch):** never model a nested/tree-shaped ESI
  resource with a self-referential Go struct. Not applicable to this batch's models (all flat or
  simple slices) — already sandbox-verified with a live `mcpsdk.AddTool`+`Connect` registration
  test with zero schema-generator errors, but Task 2 must still run the real
  `go test ./... -race` before commit, not just build/vet.
- This plan's code has already been verified to compile clean (`go build`/`go vet`/`gofmt -l`)
  against the real installed dependencies in an isolated sandbox, AND (for the `mcp/` layer) to
  pass a live `mcpsdk.AddTool`+`Connect` registration test with zero output-schema errors — see
  `docs/superpowers/specs/2026-07-26-esi-mail-design.md` for the verification detail.

// Package esi's mail.go covers all 9 of "Mail"'s endpoints. All 9 are private/"my own character"
// -- verified against esi/api/openapi.yaml's security blocks, every one of the 9
// /characters/{character_id}/mail... paths requires an esi-mail.{read_mail,send_mail,organize_mail}.v1
// character-scoped OAuth2 scope, never a caller-supplied character ID.
//
// CharacterMailHeaders' pagination is NOT the page/X-Pages style used elsewhere in this project
// (see totalPagesFromHeader in esi/contracts.go) -- verified from the generated request builder's
// own optional params (esi/api_mail.go's ApiGetCharactersCharacterIdMailRequest), ESI's mail
// listing endpoint offers only an optional `labels []int64` filter plus a `lastMailId *int64`
// cursor for paging backwards through older mail; there is no page number or total-pages header.
package esi

import (
	"context"
	"fmt"

	esiapi "github.com/fnt-eve/goesi-openapi/esi"
)

// CharacterMailHeaders returns up to the 50 most recent mail headers for the client's own
// character, optionally filtered to labelIDs and/or paged backwards from lastMailID (both
// verified from the generated request builder -- ESI's mail listing has no page-number/X-Pages
// pagination, only this label-filter-plus-cursor scheme). An empty labelIDs and lastMailID=0 omit
// both query parameters.
func (c *Client) CharacterMailHeaders(ctx context.Context, labelIDs []int64, lastMailID int64) ([]esiapi.CharactersCharacterIdMailGetInner, error) {
	req := c.api.MailAPI.GetCharactersCharacterIdMail(ctx, int64(c.characterID))
	if len(labelIDs) > 0 {
		req = req.Labels(labelIDs)
	}
	if lastMailID > 0 {
		req = req.LastMailId(lastMailID)
	}
	result, resp, err := req.Execute()
	if err != nil {
		return nil, fmt.Errorf("get character mail: %w", describeError(err, resp))
	}
	return result, nil
}

// CharacterMailLabels returns the client's own character's mail labels, their individual unread
// counts, and the total unread count across all mail.
func (c *Client) CharacterMailLabels(ctx context.Context) (*esiapi.CharactersCharacterIdMailLabelsGet, error) {
	result, resp, err := c.api.MailAPI.GetCharactersCharacterIdMailLabels(ctx, int64(c.characterID)).Execute()
	if err != nil {
		return nil, fmt.Errorf("get character mail labels: %w", describeError(err, resp))
	}
	return result, nil
}

// CharacterMailLists returns every mailing list the client's own character is subscribed to.

// MailHeader mirrors CharactersCharacterIdMailGetInner. Every field is a pointer because ESI

	From       *int64          `json:"from,omitempty"`

func toMailHeaders(headers []esiapi.CharactersCharacterIdMailGetInner) []MailHeader {
	out := make([]MailHeader, len(headers))
	for i, h := range headers {
		out[i] = MailHeader{
			MailID: h.MailId, From: h.From, Subject: h.Subject, Timestamp: h.Timestamp,
			IsRead: h.IsRead, Labels: h.Labels, Recipients: toMailRecipients(h.Recipients),
		}
	}

// minMailID returns the lowest non-nil MailID across headers, for ListCharacterMailOutput's
// NextLastMailID -- see that field's own doc comment for why.
func minMailID(headers []MailHeader) *int64 {
	var min *int64
	for _, h := range headers {
		if h.MailID == nil {
			continue
		}
		if min == nil || *h.MailID < *min {
			min = h.MailID
		}
	}
	return min
}
