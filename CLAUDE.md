# neat — New Eden Agent Toolkit

Go MCP server + Claude Code plugin for interacting with EVE Online via Fenris Creations' (FC's) ESI API and a local copy of FC's Static Data Export (SDE). It also works in the Claude desktop app and other MCP clients through a manual config entry (see `README.md`); no packaged Desktop extension exists. User docs: `README.md`. Developer guide: `docs/README.md`. Tool reference: `docs/reference/tools.md` (generated). Design spec: `docs/superpowers/specs/2026-07-23-foundation-design.md`.

## Architecture

Flat package structure at repo root. No `internal/`. One package per responsibility:

| Package | Responsibility |
|---|---|
| `cmd/` | `main.go` entrypoint only |
| `commands/` | `urfave/cli/v3` command tree (`version`, `setup`, `mcp`, `analytics on\|off\|status`). `setup`'s keychain check prints a wait notice if it hasn't returned after 5 seconds (a locked keychain blocks on an unlock prompt, which may open on another display), and a failed check ends with an OS-specific hint (Linux: the Secret Service's default keyring) |
| `analytics/` | Anonymous usage statistics via Aptabase (one file, `analytics.go`). Two events only. `app_started`: sent once per `neat mcp` launch in a background goroutine (`commands/mcp.go`'s `startAnalytics`), carrying `appVersion`, `osName` from `runtime.GOOS`, prop `arch` from `runtime.GOARCH`, its own random session ID, and prop `monthlyId`, 128 random bits saved in `~/.neat/analytics.json` and replaced at each new UTC calendar month, so distinct IDs per month give monthly users without linking months. `tool_called`: one per tool call, recorded by `ToolMiddleware` (MCP receiving middleware added in `commands/mcp.go`, so `mcp/` and every tool are untouched), carrying only props `tool` and `outcome` (`ok`/`error`, from `CallToolResult.IsError`) under a second, separate session ID and with no `monthlyId`, so tool use can't be joined to an install. At startup `RegisteredTools` lists the server's own tool names over an in-memory session, and the middleware records only calls whose name is in that set, so `tool` is always a registered tool name, never client-supplied text. A call counts as `error` when its result has `IsError` or it ends in a Go error (e.g. output-schema validation, or a raw handler's error); the SDK can return a typed-nil `*CallToolResult` there, so check for nil before reading `IsError`. A `ToolTracker` queues them in memory (capped at 1000), flushes in batches of 25 every minute (each periodic flush on its own 5-second context, so stopping `Run` never cancels a batch mid-send) and once on shutdown (3-second timeout, after waiting for `Run` to return), and drops a batch that fails rather than retrying or persisting it. `neat mcp` turns SIGINT/SIGTERM into a cancelled context (`signal.NotifyContext`) and treats that as a clean exit, so the final flush and the SDE close still run when a client stops it with a signal. Everything is best-effort and logged only at debug level. The app key is injected via `-ldflags -X main.aptabaseAppKey`; empty sends nothing. `-X main.analyticsDebug=true` (set by the Makefile, never by GoReleaser) marks every event as Aptabase debug data, as does version `dev`, so only release builds count as users; and the key's region (`A-EU-`/`A-US-`) picks the host. Opt-out is `config.Config.AnalyticsDisabled` (`neat analytics off`, which also deletes the ID file); a nil `*ToolTracker` records nothing |
| `config/` | Non-secret state in `~/.neat/config.json`: logged-in characters with the user's account label (`Account`: characters with the same label share an EVE account; empty means unknown, never "its own account") and `Notes` for each (`characters.go`: `UpsertCharacter` keeps both when a character is re-added; `SetCharacterAccount`, `RenameAccount`, `DeleteAccount`, `UnlabelledCharacters`, which is empty with fewer than two characters), named facility, haul and hub profiles for planning builds, routes, hauls and purchases, and the `analyticsDisabled` opt-out |
| `creds/` | OS keychain wrapper (`zalando/go-keyring`), service name `"neat"` |
| `sso/` | ESI OAuth2/PKCE login flow: state generation, a loopback browser session for the redirect (`session.go`: an HTTP server on `127.0.0.1:48211`, bound only while `add_character` runs, serving `/callback` plus a page listing the user's characters with "Add another character" and "I'm done" buttons, embedded from `sso/web/`; the page groups characters by account and, given `AddOptions.Accounts` (an `AccountEditor`), lets the user move characters between accounts, create, rename and delete them through token-checked POSTs to `/account/set|rename|delete`; a character logged in right after another is shown in that one's account as an unsaved suggestion until the user confirms or changes it), orchestration via `github.com/fnt-eve/goesi-openapi`, refresh-token persistence via `creds/`. The redirect URI `http://127.0.0.1:48211/callback` must match the ESI application's registered callback URL exactly, so the port is fixed. The session ends when the user clicks Done, closes the tab (a `pagehide` beacon, backed by a 30-second ping timeout), or a login gets no callback within 5 minutes; it accepts only its own `Host` header (DNS rebinding) and a per-session page token on every POST (CSRF), and each OAuth2 state is single-use. `scopes.go` defines the scope groups a login can request (`ScopeGroups`; `basic` always, the rest chosen per login, so no login asks for all 72 scopes at once) and `GrantedScopes`, which reads a character's granted scopes from its current access token's `scp` claim. All outbound requests to FC (JWKS fetch, OAuth2 token exchange) carry `sso.UserAgent(version)`, per ESI's User-Agent best practices. Also caches a per-character auto-refreshing HTTP client (`AuthenticatedClient`/`RemoveCharacter`) for `esi/`'s use — refreshing relies entirely on `golang.org/x/oauth2`'s own token source (with rotated refresh tokens persisted back to `creds/` if FC ever returns one), not hand-rolled expiry tracking. `AuthenticatedClient`, `RemoveCharacter`, and `add_character`'s token save share one mutex across their entire keychain operation, not just the cache map, so none can interleave. Re-adding an already-known character (e.g. after FC revoked its refresh token) evicts that character's cached client along with saving the new token, so the fresh login takes effect immediately rather than after a process restart |
| `mcp/` | MCP server (official `github.com/modelcontextprotocol/go-sdk`) and its 261 tools, all registered in `server.go`'s `NewServer` (the navigation and hauling tools via `nav_register.go`, the trade hub and purchase tools via `market_register.go`, and the industry planning tools via `industry_register.go`; their shared SDE and ESI gathering is `planner.go`). The full list, grouped by player-facing area, is `docs/reference/tools.md`, generated by `tools/gentooldocs` from a live `NewServer` (`go generate ./...`); its test fails while that file is stale, and generation fails if a new tool matches no area in `tools/gentooldocs/main.go`'s `areas` (an area must come before any whose keywords its tools also contain, e.g. killmails before mail). `instructions.go` holds `Instructions`, sent to every client in the initialize result: onboarding (`list_characters` → `list_scope_groups` → `add_character`, always offering the corporation groups and adding `structures` for assets or industry, plus the `http://127.0.0.1:48211/` fallback when no browser tab opens), scope errors, corporation tools refused for in-game roles (try one other character in the corporation, never every one, to spare ESI's error limit), adding a group to several characters in one login, confirming before write tools, and never computing industry numbers. It's the only guidance clients without plugin skills (e.g. Claude Desktop) get, so keep it consistent with the skills. Notable tools: `add_character` (one call can add several characters through the browser session page; returns them all; grants the `basic` scope group plus the `scopeGroups` asked for, and with `characterId` re-authorizes a character keeping its granted scopes, returning `warnings` if the user logged in as someone else or the old scopes couldn't be read). Write tools (`respond_calendar_event`, `add_/update_/remove_character_contacts`, fittings, fleet, mail, `set_autopilot_waypoint`, `open_*_window`) use verb-first names, say in their descriptions that they change state on EVE's server, and take no confirmation parameter. The planning tools call the pure packages below: haul profiles, `plan_jump_route` and `plan_haul` call `nav/` and `cargo/`; hub profiles and `quote_market_purchase` call `market/`; the industry tools (`save_/list_/delete_facility_profile`, `describe_facility`, `calibrate_facility_profile`, `find_owned_blueprints`, `check_build_skills`, `check_material_stock`, `estimate_*`, `solve_ore_mix`, `plan_build`) call `industry/`; the profile writers change only `~/.neat/config.json`, and `plan_build` saves its full plan under `~/.neat/plans/`. `mcp/enrich.go` holds `resolveTypeNames`, the shared SDE-backed `type_id` → name resolver that populates the `*Name` sibling fields (`TypeName`, `ShipTypeName`, ...) alongside the bare `*ID` fields ESI returns, across 44 tools in 19 non-Universe files (`assets.go`, `contracts.go`, `killmails.go`, `market.go`, `industry.go`, `wallet.go`, ...). It deduplicates IDs per call and drops failed lookups rather than erroring — enrichment is additive, so one bad ID must never fail a tool call over data ESI already returned. Batch 2 extended `mcp/enrich.go` with six sibling resolvers (`resolveSystemNames`/`resolveRegionNames`/`resolveConstellationNames`/`resolveStationNames`/`resolvePlanetNames`/`resolveMoonNames`) covering the same additive-`*Name` pattern for system/region/constellation/station/planet/moon IDs across 14 more files. Batch 3 further extended `mcp/enrich.go` with four sibling resolvers (`resolveRaceNames`/`resolveBloodlineNames`/`resolveFactionNames`/`resolveGroupNames`) covering the same additive-`*Name` pattern for race/bloodline/faction/group IDs across 8 more files, closing out batch 1's originally-flagged follow-up list. The Wallet tag's two wallet-transactions tools (`list_character_wallet_transactions`/`list_corporation_wallet_transactions`) adopt the same `TypeName` enrichment via `resolveTypeNames`, bringing `wallet.go` into the enriched-file set for the first time. The Cosmetics tag adds two SDE-only sibling resolvers, `resolveSkinrComponentNames`/`resolveSkinrSlotNames`, enriching `get_skinr`'s slots and `list_character_skinr_component_licenses` with component and slot names (alongside `get_skinr`'s `ShipTypeName` via `resolveTypeNames`). |
| `nav/` | Pure calculations for moving ships and characters through New Eden, for any activity (PvP, PvE or industry), not only builds — no network, disk or clock access, and no other neat imports; `mcp/nav_*.go` gathers SDE, ESI and config inputs and calls it. Security bands (highsec, lowsec, nullsec incl. Pochven/Zarzakh, wormhole), the displayed security value and its in-game color (`SecurityOf`, carried on every route leg and on `get_universe_system`), and where a cyno can be lit; jump fuel, range and fatigue (EVE's 9.46e15 m light year, fuel rounded per jump — matches dotlan to the unit); jump/gate route search with pilot preferences and dotlan links. Every number the SDE doesn't carry is a sourced constant in `nav/constants.go`. Design: `docs/superpowers/specs/2026-11-20-logistics-planning-design.md` |
| `cargo/` | Pure calculations for what fits where — no network, disk or clock access, and no other neat imports: item volumes (assembled for a singleton, packaged otherwise); `Inventory`, which lays out everything at one station or structure in tree order (corporation offices transparent) with each assembled ship's assembled and packaged volume, what comes out of it to repackage it and the rigs that destroys (strategic cruisers keep theirs), and totals for a move (backs `list_location_assets`; output is a flat list with `parentItemId`/`depth`, since MCP output can't be self-referential); packing a cargo list into loads that fit a hold, each an even slice of everything. Constants in `cargo/constants.go`. Design: `docs/superpowers/specs/2026-11-20-logistics-planning-design.md` |
| `market/` | Pure buying calculations for any purchase, not only build materials — no network, disk or clock access, and no other neat imports; `mcp/market_*.go` calls it: walking a sell order book for a quantity at a station, and in-game Multibuy lists. Design: `docs/superpowers/specs/2026-11-20-logistics-planning-design.md` |
| `industry/` | Pure industry calculations — no network, disk or clock access; `mcp/industry_*.go` gathers SDE, ESI and config inputs and calls it. Imports `nav/` (security bands), `cargo/` (haul loads) and `market/` (order books); none of them import it, so nothing about moving or buying depends on industry. Facility bonuses resolved from the SDE's own `indModifierSources`/`indTargetFilters` tables and dogma attributes for every facility kind (NPC station, Upwell structure, starbase) in every security band; per-job material rounding, job time, job fees (or a calibrated rate), ME/TE research, copying and invention; blueprint tree expansion with build/buy decisions, owned copies and stock netting; build-vs-buy; Upwell and NPC reprocessing yield; the compressed-ore linear program (`gonum.org/v1/gonum/optimize/convex/lp`); job scheduling across builders. Every number the SDE doesn't carry is a sourced constant in `industry/constants.go`. Design: `docs/superpowers/specs/2026-11-18-industry-planning-design.md` |
| `esi/` | Thin facade over `github.com/fnt-eve/goesi-openapi`. `NewClient` builds a per-character authenticated ESI API client from `sso.AuthenticatedClient`'s cached, auto-refreshing HTTP client; `NewClient` also checks every request against `scopes_gen.go`, a table of each ESI endpoint's required scope ("" for public ones) generated by `tools/genscopes` from the OpenAPI spec bundled in `goesi-openapi` (`go generate ./esi/`; rerun after bumping it). A request for an endpoint whose scope the character's access token doesn't carry fails before it is sent with `*esi.MissingScopeError`, whose message names the scope group and tells the agent to re-authorize via `add_character` with `characterId` and `scopeGroups`; the most specific template wins, so public endpoints are in the table too. `NewPublicClient` builds an unauthenticated client for resource groups where every endpoint is public (e.g. Alliance — no character needed at all). Holds no state of its own. Covers one ESI resource group ("tag") per file (`wallet.go`, `access_list.go`, `activities.go`, `alliance.go`, ...) — see `docs/reference/esi-coverage-roadmap.md` for what's covered and what's left across all 39 tags (the original 36, plus Military Campaigns, Cosmetics, and Paragon Hub, all implemented since goesi-openapi v0.0.42 / compatibility date 2026-08-18). `esi.AllPages` walks every page of any paginated call. |
| `sde/` | Local cache of fuzzwork.co.uk's periodically-refreshed SQLite conversion of FC's Static Data Export (`~/.neat/sde/eve.db`), queried directly via `database/sql` + `modernc.org/sqlite` — no intermediate key-value store. Lazily syncs on first lookup call per `Store` lifetime (at most once per `neat mcp` process run): an ETag-gated download+gunzip+atomic-rename of the dump (sync-fatal on failure) plus narrow fetches from EVE Ref for the three fields with no source in the dump, saved to `~/.neat/sde/everef.json` and downloaded again only when the archive's etag in EVE Ref's `index.json` changes (`sde/everef.go`) — best-effort: type `Radius` from the `reference-data` export (fuzzwork dropped `invTypes.radius`; found in the 2026-11-18 audit), and race `AllianceID`/graphic `SofDNA` from the `esi-scrape` export. Type `PackagedVolume` used to come from `reference-data` too, until FC added it to the SDE itself (esi-issues#1499); fuzzwork's dump now carries it as a plain `invTypes.packagedVolume` column, read directly like `mass`/`volume`. `PutX`'s cache-miss write-back lands in a process-lifetime in-memory overlay, not the downloaded file itself, which is treated as read-only. Backs 24 of the Universe tag's 30 tools via a read-through cache (`mcp/universe.go` orchestrates the ESI fallback and write-back; `sde/` itself never imports `esi/`) — the other 6 are permanently ESI-direct by design (live/non-cacheable data). Four fields are permanently unsourced across every dataset checked: `get_universe_graphic`'s `CollisionFile`, `get_universe_region`'s `Description`, `get_universe_station`'s `Services`, and `list_universe_factions`'s `IsUnique` — see `docs/superpowers/specs/2026-08-04-sde-sqlite-migration-design.md` for how each was found and why none were solved with an additional data source. Also serves two SDE-only lookups with no ESI resource behind them at all (so no read-through fallback or overlay): SKINR components (`skinrComponents`) and cosmetic slots (`skinrSlots`), backing the Cosmetics tag's name enrichment. It also serves industry planning (`sde/industry.go`, `sde/dogma.go`, `sde/routing.go`): blueprints by type and by product, reprocessing outputs, compressed ores, NPC station reprocessing data, dogma attributes, rig modifiers, the `indModifierSources`/`indTargetFilter*` tables, and every system's position, security and stargates for routing. Those accessors return `sde.ErrUnavailable` instead of a silent miss, since planning has no ESI fallback. `sde.OpenStatic` opens a dump without ever syncing; `sde/sdetest` uses it to build fixture databases for other packages' tests. |
| `tools/` | Code generators and CI checks, each its own `main` package: `genscopes` (`esi/scopes_gen.go`), `gentooldocs` (`docs/reference/tools.md`), `genversion` (plugin manifest version) and `versiongate` (the PR check that `VERSION` was bumped). |

## Known gaps (tracked, not silently accepted)

- ~~FC added a 37th ESI tag, "Military Campaigns" (6 endpoints), blocked on an upstream `goesi-openapi` release.~~ Resolved in the 2026-11-18 SDE/ESI audit: `goesi-openapi` v0.0.42 (generated against compatibility date 2026-08-18) ships bindings for it plus two more tags FC added since, Cosmetics (3) and Paragon Hub (5), and all 14 endpoints are now implemented. See `docs/reference/esi-coverage-roadmap.md`.
- **EVE Ref's `esi-scrape` dataset has not been regenerated since 2025-11-26** (found in the 2026-11-18 audit: EVE Ref's own `esi-scrape/index.json` gives `eve-ref-esi-scrape-latest.tar.xz` a `last_modified` of 2025-11-26T15:42:24Z, the archive's `status.yaml` snapshot is of server build 3116156 started that morning, and `history/2025/` ends with that day's snapshot; Cloudflare's `Last-Modified` header looks current but is synthesized at the edge, differing between simultaneous requests). `sde/` still fetches it for race `AllianceID` and graphic `SofDNA`, which are rarely-changing enough that a year-stale copy is still correct for every existing race and nearly every graphic, but anything FC added since is missing from it. EVE Ref's still-current `reference-data` export has no race or graphic files, so it can't replace `esi-scrape` for these two (it does replace it as type `Radius`'s source -- see Hard rules). Revisit if EVE Ref resumes publishing, or if a graphic's `SofDNA` going missing turns up in practice.
- ~~No CI configuration exists in this repo at all.~~ Resolved: `.github/workflows/test.yml` runs `go build`/`go vet`/`go test -race` on real `ubuntu-latest`, `macos-latest`, and `windows-latest` runners on every push/PR.
- ~~Cross-process TOCTOU in `sso.bindExclusive`'s stale-socket recovery path.~~ Gone with the Unix-socket handoff: a second `neat` process is now kept out by the exclusive TCP bind of the callback port, which the OS makes atomic, and a crashed process leaves no file behind to recover.
- ~~The browser tab never closes/navigates after a successful `add_character` login.~~ Resolved by moving the OAuth2 redirect from the `eveauth-neat://` custom scheme to a loopback HTTP server (`docs/superpowers/specs/2026-11-19-loopback-oauth-callback-design.md`): FC's tab now lands on neat's own page.
- **The callback port is fixed (48211)**, because FC's SSO matches the registered callback URL exactly and doesn't implement RFC 8252 §7.3's any-port loopback matching. If another program holds the port, `add_character` fails with an error naming it rather than falling back. Revisit if FC ever accepts any-port loopback redirects.
- **Installs that ran neat 0.7.x or earlier keep their old `eveauth-neat://` registration**: `~/.neat/NeatURLHandler.app` registered with Launch Services on macOS, `HKCU\Software\Classes\eveauth-neat` on Windows, and `~/.local/share/applications/neat-url-handler.desktop` on Linux, plus the launcher copy at `~/.neat/bin/neat`. Nothing redirects to that scheme any more, so they sit inert; no code removes them, and a user can delete them by hand. Same trade-off as the orphaned bbolt file below.
- **`~/.neat/sde/sde.db` (the old bbolt cache file) is orphaned by the sqlite migration** and never
  cleaned up automatically -- no migration code deletes it, so it sits inert on disk for any
  install that previously ran the bbolt-backed `sde/`. A user can delete it by hand; see
  `docs/superpowers/specs/2026-08-04-sde-sqlite-migration-design.md`'s "Fetch & freshness" section.
- **`sde.Store`'s in-memory overlay (`PutX`'s cache-miss write-back) is invisible to every
  `*IDs`/list accessor** (`RegionIDs`, `TypeIDs`, `Factions`, ...) -- they query the sqlite dump
  only. A `GetX(id)` can succeed for an ID a `PutX` just wrote back from a live ESI fetch, while
  the matching `*IDs()`/list call never includes it, since the two paths look at different stores.
  Surfaces only for a genuinely new ID FC added after the fuzzwork dump's last refresh -- rare,
  self-healing at the next refresh. Deliberately not fixed by merging overlay entries into every
  `*IDs`/list result: real complexity for an edge case that resolves itself. See `sde/store.go`'s
  `overlay` field doc comment.

## Hard rules

- **Prefer a cached, statically-refreshed source over a live per-request ESI call**: any tool needing a resource available from FC's SDE or from EVE Ref's `esi-scrape` bulk export must read it from `sde/`, never call ESI for it directly. Performance and API-citizenship requirement, not a suggestion. `sde/` is backed by a single downloaded file — fuzzwork.co.uk's SQLite conversion of FC's SDE, ETag-checked and re-downloaded once per process lifetime on change (sync-fatal on failure) — queried directly via SQL, no intermediate key-value store. Three fields with no source in that file come from narrow fetches against EVE Ref (best-effort — a fetch or parse failure there logs a warning and falls back to the last saved values, or skips that field's augmentation if none were saved, never failing the rest of the sync): race `AllianceID` and graphic `SofDNA` from the `esi-scrape` dataset, and type `Radius` from the `reference-data` dataset. Type `Radius` moved there in the 2026-11-18 audit, when fuzzwork dropped `invTypes.radius`; until `sde/type.go` stopped selecting it, every `Type` lookup failed with "no such column: radius", which broke `get_universe_type` outright and silently blanked every `TypeName` enrichment. Type `PackagedVolume` was sourced from `reference-data` too, until FC added it to the SDE itself (https://github.com/esi/esi-issues/issues/1499) and fuzzwork's dump picked it up as a plain `invTypes.packagedVolume` column — `sde/type.go`'s `Type` reads it straight off that column, same as `mass`/`volume`/etc. 24 of the Universe tag's 30 tools are `sde/`-backed via a read-through cache: try `sde/` first, fall back to a live ESI call on a cache miss, write the result back (into a process-lifetime in-memory overlay, not the downloaded file, which is treated as read-only) so the next lookup of that ID is fast. The other 6 (`list_universe_structures`/`get_universe_structure`, `list_universe_system_jumps`/`_kills`, `resolve_universe_ids`/`_names`) are permanently ESI-direct by design -- they resolve live, non-cacheable data (structures are player-owned and access-gated; jumps/kills are moment-in-time activity counters; the resolve tools take arbitrary caller-supplied names/IDs), not an SDE sourcing gap. Four fields have no source anywhere in the fuzzwork dump: `get_universe_graphic`'s `CollisionFile` (also absent from EVE Ref's `esi-scrape` mirror of ESI's own live responses -- unaffected by the sqlite migration), `get_universe_region`'s `Description` (`mapRegions` has no description column at all -- a genuine regression from the prior bbolt design, which sourced it from FC's own jsonl), `get_universe_station`'s `Services` (`staOperationServices` has zero rows in the dump), and `list_universe_factions`'s `IsUnique` (`chrFactions` has no `uniqueName`-equivalent column). Each is populated on a cache miss (fresh off ESI) but not on a cache hit -- documented in `docs/superpowers/specs/2026-08-04-sde-sqlite-migration-design.md`'s field-drop findings. The `reference-data`/`esi-scrape` archives (about 57 MB and 77 MB) are gated too, but not by HEAD: data.everef.net sends no ETag, and its Last-Modified is Cloudflare's edge cache-fill time, which differs between requests. Each `sync()` instead reads the dataset's `index.json` (a few hundred bytes), whose per-file `etag` is the origin's own, and downloads an archive only when that etag differs from the one saved in `~/.neat/sde/everef.json` with the extracted values (`sde/everef.go`). If the index can't be read, the archive is downloaded as before; if that download fails, the saved values are used.
- **Industry bonuses come from the SDE, not code**: structure role bonuses, rig bonuses and each rig's own security multipliers, which products each rig or structure affects (`indModifierSources` + `indTargetFilter*`), refinery yield bonuses, implant bonuses and jump drive attributes are all read from the fuzzwork dump at use time. The only numbers kept in code are those with no SDE source, each a named constant in its package's `constants.go` citing where it comes from: `industry/constants.go` (SCC surcharge, Alpha tax, tax cap, NPC facility tax, reprocessing base and rig/security terms, invention base chances and decryptors, research level durations) and `nav/constants.go` (the light-year constant, jump fatigue limits). Facts ESI can't see (fitted rigs and services, owner taxes, hauling hull and routes, routing preferences) live in saved profiles in `~/.neat/config.json`, never as hard-coded assumptions.
- **Logins request scope groups, never every scope**: `add_character` asks FC for the `basic` group plus the groups the user picked (`sso/scopes.go`), and a tool needing more fails with `esi.MissingScopeError` until the user re-authorizes. Requesting all scopes in one login pushed FC's login-site cookies past its request-header limit after a couple of logins ("HTTP Error 400. The size of the request headers is too long"). Every scope an ESI endpoint needs must belong to exactly one group; `esi`'s and `sso`'s tests enforce it, so a `goesi-openapi` bump that adds an endpoint with a new scope fails CI until the scope is grouped.
- **Analytics send nothing that identifies a person or machine**: `analytics/` sends exactly two events. `app_started` carries only the version, the build's `runtime.GOOS`/`runtime.GOARCH`, its session ID and the monthly random ID. `tool_called` carries only the registered tool name and `ok`/`error`, plus version and OS name, under a separate session ID and never the monthly ID. Never add character IDs or names, tool arguments, results, error text, durations, paths, hostnames, locale, OS version, hardware identifiers or any persistent ID to either, never put the monthly ID or `app_started`'s session ID on `tool_called`, never make the monthly ID outlive its month, and never write queued events to disk. Any change to what is sent changes `PRIVACY.md`'s "Anonymous usage statistics" section in the same commit. Users opt out with `neat analytics off`; that must stay one command and must stop all sending.
- **No environment variables for config/credentials.** Config lives under `~/.neat/`; credentials
  live in the OS keychain only.
- **No client secret.** The ESI app is a PKCE-only public app — nothing secret ships in the binary.
- **ESI User-Agent compliance**: every outbound request to FC's login/ESI endpoints must carry `sso.UserAgent(version)`. FC's best-practices guidance treats non-compliant User-Agents as grounds for a temporary ban — see `sso/useragent.go`.
- **ESI error detail must not be discarded**: every `esi/` method that calls `.Execute()` on a generated API request must route its error and `*http.Response` through `describeError` (`esi/error.go`) before wrapping and returning it. `goesi-openapi`'s generated error type degrades to a bare HTTP status string on its own — its message formatter looks for `Title`/`Detail` fields via reflection, but ESI's actual error model uses `Error`/`Details` instead, so the real detail (invalid scope, expired token, etc.) and the `X-Esi-Error-Limit-Remain`/`-Reset` rate-limit headers are silently lost unless routed through this helper. Confirmed via direct reproduction against `goesi-openapi` v0.0.37 — see `esi/wallet.go` for the pattern every new `esi/` method should follow. When no ESI error detail can be extracted, notably when a 2xx response fails to decode into the generated model, `describeError` appends the raw response body (truncated to 512 bytes) instead, so the error shows what ESI actually sent rather than only what the model expected.

- **Developer License Agreement notice is verbatim**: the end of `README.md`, the end of `PRIVACY.md` and the footer of `sso/web/page.html` carry the proprietary notice from section 7.1 of https://developers.eveonline.com/license-agreement exactly as the agreement words it, including "CCP hf.". It is the one place the old company name stays: elsewhere use Fenris Creations in introductory text and FC everywhere else. Change its wording only if the agreement's own text changes.

## Conventions

- Wrap errors with context: `fmt.Errorf("operation: %w", err)`. Never discard an error (`_ = err`).
- External test packages by default (`package foo_test`); use `*_internal_test.go` only when a
  test genuinely needs an unexported symbol.
- Table-driven where a table naturally fits (many input variations on one code path);
  independent, clearly-named tests otherwise — don't force behaviorally distinct scenarios into
  one table just to have a table. Standard library only, either way — no `testify` or other
  assertion libraries.
- `creds/` tests must call `keyring.MockInit()` before touching keychain functions — never let
  tests hit the real OS keychain.
- Never model a nested/tree-shaped ESI resource with a self-referential Go struct (a type whose
  field is `[]ThatSameType`). It passes `go build`/`go vet`/`gofmt` but panics at server startup
  ("cycle detected for type ...") in the MCP SDK's output-schema generator — only `go test ./...`
  actually calling `mcpsdk.AddTool` catches it. Instead, define one distinct, non-recursive type
  per real nesting level, matching the ESI schema's actual depth (see `mcp/killmails.go`'s
  `KillmailItem`/`KillmailInnerItem` split).

## Keeping docs & Claude resources in sync

`neat` is consumed by both humans and agents through several surfaces that must not drift from the
code. **When a change affects behavior, update the relevant surfaces in the same commit/PR** —
treat it as part of "done," not a follow-up:

- **User docs** → `README.md` is for EVE players, not developers: what neat is, example questions, install (release binary, Claude Code plugin, Claude desktop config), choosing scope groups, where data lives, troubleshooting, and a short Development section. Keep big tables and implementation detail out of it; they belong in `docs/README.md`, `docs/reference/` or this file. Update it when installation, login, scope groups, data locations or user-visible errors change. It ships inside every release archive, so it must stand alone.
- **Packages / architecture** → the package table and conventions in **this `CLAUDE.md`**, and the package list in `docs/README.md`. Note significant departures from `docs/superpowers/specs/2026-07-23-foundation-design.md` in that spec's own status line rather than rewriting it — it's a historical record of what was decided, not a living doc.
- **MCP tools** (added, renamed or redescribed) → run `go generate ./...` to regenerate `docs/reference/tools.md`, placing any new tool in an area in `tools/gentooldocs`. Tool counts appear only in that generated file and this file's `mcp/` row; keep counts out of `README.md` and the plugin and marketplace manifests, which drift.
- **Server instructions** (`mcp/instructions.go`) → when onboarding, scope handling or write-tool behavior changes, update them alongside the skills that cover the same ground.
- **CLI surface** (new command, flag, or exit-code contract) → `README.md`'s install steps, `docs/README.md`, and this file's package table.
- **Credentials** (new keychain key, service name, or verification flow) → `creds/`,
  `commands/setup.go`, and the Hard rules / Conventions sections here.
- **Hard rules** (SDE-vs-ESI routing, no client secret, no env vars for storage) → keep these
  listed here exactly as they're enforced in code; if a rule is relaxed or tightened, this file
  changes in the same commit as the code that changes it.
- **Plugin skills** (`claude_resources/neat/skills/*/SKILL.md`: `add-character`, `industry-build-plan`, `industry-profile-setup`, `haul-route-setup`) → when `add_character`'s or an industry, hauling or routing tool's inputs, outputs or behavior change, or a scope group changes, update the skill that drives it in the same commit. Skills hold discovery and decision steps only — never formulas or arithmetic.
- **Plugin packaging** → `claude_resources/README.md` (developer-facing: contents, skills, testing a local build), `claude_resources/neat/CHANGELOG.md` (user-facing release notes, one entry per `VERSION`), and the descriptions in `claude_resources/neat/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`.
- **Agent-facing surfaces that don't exist yet** — once built in a later plan, add them to this list: a packaged Claude Desktop extension (`extension/manifest.json`), which would replace the README's manual desktop config. Don't leave a plan's own doc updates (e.g. its plan file, or a spec status line) as a "follow-up" task.

Before opening a PR, sanity-check that `README.md`, `docs/README.md` and this file still describe what the code actually does.

## Build

`clientID` (the ESI OAuth2 client ID, `esiClientId`) and `aptabaseAppKey` (optional; empty sends no analytics) are injected via `-ldflags` from the git-ignored `app_config.json` — `make build` wraps this for local development. Releases read them from the `ESI_CLIENT_ID` and `APTABASE_APP_KEY` repository variables.

```bash
go build -ldflags "-X main.version=$(cat VERSION 2>/dev/null || echo dev) -X main.clientID=$(jq -r '.esiClientId // .clientId' app_config.json) -X main.aptabaseAppKey=$(jq -r '.aptabaseAppKey // ""' app_config.json) -X main.analyticsDebug=true" -o neat ./cmd
```

`make install` builds and installs `neat` to `~/.local/bin` (override with `PREFIX=...`). It removes the old binary before copying the new one, because on macOS copying a build over an existing binary in place makes the kernel kill it on launch (exit 137); if you install by hand, `rm` first.

```bash
make install
```

## Versioning & Release

The top-level `VERSION` file is the single source of truth for the `neat` binary version, the Claude Code plugin manifest version, and the release git tag. `tools/genversion` (wired via `go:generate` in `cmd/main.go`) propagates it into `claude_resources/neat/.claude-plugin/plugin.json` — run `go generate ./...` after bumping `VERSION` and commit the result.

`tools/versiongate` is a required PR check: any PR touching release-significant files (Go source, `go.mod`/`go.sum`, `.goreleaser.yaml`, anything under `claude_resources/`) must bump `VERSION`. Docs, tests, and CI config are exempt. There is no override — bump it. Add a matching entry to `claude_resources/neat/CHANGELOG.md`.

Merging to `main` triggers `.github/workflows/release.yml`, which tags `v<VERSION>` (if that tag doesn't already exist) and runs GoReleaser to build/publish `neat` for linux/darwin/windows.
